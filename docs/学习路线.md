### 为什么这两章对 agent 开发格外重要

agent 的代码基本就是这四件事的排列组合：

```js
// 1. 工具注册表 —— Map + 解构 + 展开
const tools = new Map();
tools.set('read_file', { name: 'read_file', schema: {...}, execute: readFile });

// 2. 工具工厂 —— 闭包捕获配置
const createTool = (name, fn) => ({ name, execute: fn });

// 3. 装饰器式包装 —— 高阶函数（重试 / 超时 / 日志）
const withRetry = (fn, times = 3) => async (...args) => { /* 闭包保存 times */ };

// 4. 处理 LLM 返回 —— 可选链 + 空值合并 + JSON
const args = JSON.parse(msg.tool_calls?.[0]?.function?.arguments ?? '{}');
```

`Map` 而不是对象的原因：工具的 key 可能重复、需要保持注册顺序、频繁增删。这些"为什么"就是「函数进阶」那章的价值。

### 对象（基础知识）章节：必学，而且是 agent 开发的地基

agent 里所有东西都是对象：消息、工具定义、参数、配置、事件。这一章看着简单，但有 4 个点直接决定你写的 agent 有没有隐蔽 bug：

| 坑 | 现象 | agent 场景 |
|---|---|---|
| `const` 不冻结内容 | `const tool = {...}; tool.x = 1` 合法 | 配置被下游偷偷改掉，难排查 |
| 展开/`Object.assign` 是**浅拷贝** | `[...history][0].content = 'x'` 改到了原对象 | **改动对话历史污染上下文**，这是 agent 最经典的 bug |
| `in` 会查原型链 | `'toString' in {}` 为 `true` | 校验工具参数时必须用 `Object.hasOwn` |
| 方法取出后 `this` 丢失 | `const f = obj.run; f()` 非严格模式下 `this` 是全局对象 | 工具注册时 `{ execute: tool.execute }` 直接空指针 |

结论：**必学**，但重点不是"怎么创建对象"，而是**引用、浅拷贝、`this`、原型链这四件事的边界**。`Object.keys/values/entries`、解构、`?.` 必须条件反射。
垃圾回收的算法细节（标记清除）可以跳过，知道"闭包和未移除的监听器会造成泄漏"即可。

## 三、Java → JS/TS 对照表（踩坑清单）

| 概念 | Java 直觉 | JS/TS 真实行为 | 记住 |
|---|---|---|---|
| `===` | `equals()` | 对象比较是**引用**；没有 equals/hashCode | `Set`/`Map` 去重会失灵 |
| 空值 | 抛 NPE | 属性不存在返回 `undefined`，继续取才炸 | 用 `?.` 和 `??` |
| 箭头函数 | lambda | **捕获**定义处的 `this` | 回调里永远用箭头函数 |
| 普通函数 | 方法 | `this` 由**调用方式**决定 | 这是 JS 最深的坑 |
| 继承 | 单继承 | 原型链 + class 语法糖 | 日常按 Java class 写就行 |
| 并发 | Thread / 线程池 | 单线程 + 事件循环，IO 全异步 | 没有"阻塞等待"，只有 await |
| 类型 | 泛型擦除 | **运行时完全不存在类型** | 边界数据必须 zod 校验 |
| `interface` | 必须 implements | **结构化**类型，形状对就行 | 鸭子类型 |
| 联合类型 | `sealed interface` + switch | `type A = X \| Y` + 类型收窄 | TS 更强，重点学 |
| `readonly` | `final` | 编译期只读，运行时无用 | 别指望它防篡改 |
| 模块 | package/import | ESM：`import`/`export`，支持顶层 await | 异步场景更简单 |

TS 必须掌握的十件事：`strict` 模式、结构化类型、`unknown` vs `any`、类型收窄、字面量类型、泛型约束、`Partial/Pick/Omit/Record/ReturnType`、`satisfies/as`、`.d.ts` 声明文件、zod 运行时校验。

## 四、三个 SDK 的定位（不要同时学）

| SDK | 类比 | 抽象层次 | 适合 |
|---|---|---|---|
| **pi** (`pi-ai` / `pi-agent-core`) | 手写 Servlet，内核极小 | 最低，最接近 agent 本质 | **研究**源码 |
| **opencode** | Spring Cloud 微服务（server/client 分离） | 工程化最全：session / permission / LSP | **开发产品** |
| **dsh** (DeepSeek Harness) | **Spring**（Cordis IoC，一切皆插件） | 最高 | 学架构、写插件 |

学习顺序：**手写 loop → opencode 做产品 → pi 读内核 → dsh 学插件架构**。
理由：先有"没有魔法"的体感，再看工程化，再看最小实现，最后看最重的抽象。

## 七、长期纪律

1. **48 小时规则**：学完一个概念，48 小时内必须用进自己的小项目，否则重学。
2. **两周一交付**：每两周必须有一个"能给别人演示"的东西，不能只有练习题。
3. **先跑通再理解**：agent 开发里 80% 的问题靠"打印出来看"解决，别先读完文档。
4. **一次只学一个 SDK**，比较留到有体感之后。
5. 遇到看不懂的源码，**从入口 `main`/`index.ts` 往下读**，不要随机跳。
